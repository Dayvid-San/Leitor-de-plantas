# Rule: Backend integration

The site talks to a separate Spring Boot API, `../visit-card-backend` (sibling directory, own repo/build, not part of this Next.js project). This site has no server of its own (static export, see `architecture.md`), so all of this is plain client-side `fetch` to an external origin, not a Next.js API route.

- `lib/api.ts` is the single integration point. Every call goes through it: `login`, `logout`, `isAuthenticated`, `listProjects`, `createProject`, `updateProject`, `deleteProject`, `uploadImage`, `sendContact`. Don't call `fetch` against the backend directly from a page/component, add a function here instead so auth headers and error handling stay in one place.
- Base URL comes from `NEXT_PUBLIC_API_URL` (see `env.md`), defaulting to `http://localhost:8080` for local dev against a `visit-card-backend` instance running on its default port.
- Auth is JWT, not Firebase Auth. `lib/api.ts` stores the token in `localStorage` (`visitcard_admin_token`) and attaches it as `Authorization: Bearer <token>`. `app/admin/page.tsx` calls `login()`; `app/admin/dashboard/page.tsx` guards itself with `isAuthenticated()` on mount (a one-time check, not a live listener like Firebase's `onAuthStateChanged`) and redirects to `/admin` if there's no token.
- The two project collections are exposed as REST resources by category: `GET/POST /api/projects/programmer` and `GET/POST /api/projects/research`, `PUT/DELETE /api/projects/{category}/{id}`. `app/portfolio/page.tsx` reads both categories; `app/admin/dashboard/page.tsx` is the CRUD UI. Keep the `ApiProject`/`ProjectInput` shapes in `lib/api.ts` in sync with the backend's `ProjectRequest`/`ProjectResponse` DTOs if either side's fields change.
- Image field works the same as before: either paste a URL directly into `image`, or upload a file via `POST /api/upload/{category}` (multipart), which returns an absolute URL served back from the backend's `/api/images/{id}` (the image bytes are stored in the backend's Postgres, not on disk). Both paths end up as the same `image: string` field, `app/portfolio/page.tsx` doesn't need to know which one was used.
- The contact form (`app/contato/page.tsx`) posts to `POST /api/contact` via `sendContact()`. The backend rate-limits it per IP and relays the message by email (SMTP), it does not persist submissions.
- `firebase` (the npm package) and `lib/firebase.ts` were removed when this integration replaced Firebase. If you see a stale reference to either, it's dead, not something to fix by re-adding the dependency.
